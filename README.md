# Googleカレンダー 空き時間・会議室一括検索（公開用 v1.1）

Google Apps Script（GAS）、Calendar API、Googleスプレッドシートで動くサンプルです。選択した参加者と実行者本人の共通空き時間を抽出し、会議室の空き状況も照合できます。

## できること
- 登録済みメンバーをグループ別に選択、またはメールアドレスで追加
- 「今週」「来週」「指定期間（最大31日）」から検索
- 平日10〜19時、祝日除外、1時間以上、00分/30分区切りの候補を出力
- 設定シートの会議室を一括照合
- 候補日時のコピー、会議室がある候補だけのコピー
- 各利用者本人のGoogleカレンダー権限を使って照会（推奨デプロイ設定）

## 必要なもの
- Google Workspace環境（社内メンバー・リソースの照合を想定）
- Google Apps Scriptを編集できるアカウント
- メンバーの空き時間を閲覧できる適切なカレンダー共有権限
- 日本の祝日カレンダーへのアクセス

## 初回セットアップ
1. [Google Apps Script](https://script.google.com/) で新しいプロジェクトを作成。
2. `Code.gs` をスクリプトファイル `コード.gs` に貼り付け、HTMLファイルを `index` という名前で作り `index.html` の内容を貼り付けます。
3. プロジェクト設定で「appsscript.json マニフェスト ファイルをエディタで表示する」にチェックを付け、同ファイルの内容を `appsscript.json` で置き換えます。
4. 左側「サービス」→「＋」で **Google Calendar API**（高度なサービス、v3）を有効化します。環境によってCloudプロジェクト側でCalendar APIの有効化も必要です。
5. スクリプト関数 `setupSampleSpreadsheet` を**1回だけ**実行し、権限を承認します。実行ログに表示されたスプレッドシートを開きます。
6. `メンバー` シートのサンプルメールアドレスをすべて削除し、実際の利用者/会議室の `区分 | 表示名 | カレンダーID` を記入します。「会議室」区分の行は会議室として照合します。**サンプルアドレスを残すと照会時にエラーになります。**
7. 利用者本人のGoogleカレンダーで「日本の祝日」を追加します（カレンダーIDは自動検出）。対象参加者・会議室カレンダーの「予定あり/空き」情報を参照できるよう共有設定を確認します。
8. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選択します。**次の推奨設定を守ってください。**
   - 実行ユーザー：「ウェブアプリケーションにアクセスしているユーザー」
   - アクセスできるユーザー：**組織内のユーザーのみ**（Google Workspace環境で選択できる場合）
   - **「全員（匿名を含む）」での公開はしないこと。**
9. デプロイURLを開き、権限を承認してテストします。未承認OAuthアプリの制限や組織ポリシーによりアクセスできない場合があります。
10. 「アクセスしているユーザーとして実行」の場合、各利用者に設定スプレッドシートの**閲覧権限**も必要です。設定シートには社内の名前・カレンダーIDが含まれるため、共有範囲を必ず限定してください。

### `setupSampleSpreadsheet` が使えない場合
1. Googleスプレッドシートを手動作成し、シート名を `メンバー` とします。
2. A列を「区分」、B列を「表示名」、C列を「カレンダーID」にして2行目以降にデータを入れます。
3. GASのスクリプトプロパティ `MEMBER_SPREADSHEET_ID` にスプレッドシートのIDを登録してください（GAS編集画面→プロジェクトの設定→スクリプト プロパティ）。
4. `setupSampleSpreadsheet` は実行しません。

## よくある注意・制約
- このツールは**空き時間の候補検索**であり、会議室の予約や日程確定はしません。
- 会議室の空き状況は「候補時間帯の全体を通して空いているか」で判定します。一部のみ空いている会議室は表示しません（時間帯の再分割は未実装）。
- 参加者のプライベートな予定のタイトルや説明文は取得しませんが、空き/予定ありを照合する権限は必要です。
- Freebusy APIが権限エラーを返した場合、対象を空き扱いせず、処理を停止します。
- Googleの日本の祝日カレンダーは登録済み一覧から新旧IDを自動検出します。取得できない場合も、祝日を誤って候補にしないよう停止します。**Googleカレンダーの祝日一覧の登録内容（祝日・記念日等）をそのまま除外対象**とします。企業固有の休業日には未対応です。
- 参加者・会議室IDは最大40件のAPIリクエスト上限をこのサンプル側で設けています。
- 外部ドメインのカレンダーは、相手が適切に共有していなければ検索できません。
- 共通空き時間に実行者本人の `primary` カレンダーを必ず含みます。
- 時刻はAsia/Tokyoで処理します。日本時間以外の環境では、プロジェクトとコードのタイムゾーンを統一してから確認してください。
- GAS・Calendar API・スプレッドシートには実行時間やAPI利用制限があります。
- **誰でも利用可能な公開Webサービスとしての設計・セキュリティ審査はしていません。** 社内向けのサンプルとして使用してください。
- ソースコード公開と、元の会社・組織の業務データの公開は別です。顧客名、社員名、カレンダーID、設定ファイル、認証情報をGitHubにコミットしないでください。

## v1.0からv1.1への更新（既にWebアプリをデプロイ済みの場合）
1. `Code.gs` をこのZIPの **v1.1全文**で置き換えて保存します。`index.html` と `appsscript.json` も最新版との差分を確認し、同梱版に揃えます。
2. `setupSampleSpreadsheet()` は**再実行しない**でください。既存の設定シートとスクリプトプロパティをそのまま使用します。
3. 「デプロイ」→「デプロイを管理」→対象デプロイの編集→**新バージョン**→デプロイを選択します。
4. Webアプリを更新して検索します。祝日カレンダーの旧ID・公式IDの差異によるエラーが解消することを確認します。
5. 適切な権限を持つテスト用参加者・会議室で空き時間とコピー機能を再確認します。

## v1.1 の主な変更点
- 日本の祝日カレンダーを、利用者の登録カレンダー一覧から自動検出（`ja.japanese.official#holiday@...` に対応）。
- 祝日カレンダーのイベントをCalendar APIから取得し、複数ページの結果に対応。
- 祝日カレンダーが使えないときはエラーで停止し、祝日の候補を誤って表示しない。

**検証状況：** v1.0は実際のGoogle環境で基本機能を確認済みです。v1.1はJavaScript構文・カレンダーID選択ロジック等のローカル検査までで、Google Apps Script上での再デプロイ／動作確認が必要です。
