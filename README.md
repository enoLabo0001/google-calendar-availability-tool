# Googleカレンダー 空き時間・会議室一括検索（公開用 v1.2）

Google Apps Script（GAS）＋Google Calendar API＋Googleスプレッドシートで、複数の参加者と実行者本人の共通空き時間、空き会議室を照合する**社内向けサンプル**です。コードにはサンプルアドレスのみを記載し、実際の業務データや認証情報は含めていません。

## v1.2 の追加機能

- **Webアプリからのメンバー登録**：メールアドレスを手入力して検索に追加した際、「次回も使うためにマスターに登録しますか？」と確認。必要な場合だけ表示名・区分を指定してスプレッドシートに保存します（「しない」なら今回だけの追加）。保存したメンバーはWebアプリを**再読み込みしたとき**プルダウンに表示されます。
- **メーリングリストの一括展開**：管理スプレッドシートにGoogleグループのアドレスを入力し、上部メニュー **「📋 メーリス管理」→「メンバーを一括登録・更新」** から所属ユーザーのアドレスを展開します。メニューはシートを開いたときに表示されますが、**編集時や起動時の自動展開は行いません**。
- 参加者・会議室のプルダウン表示、既存の空き時間検索・会議室照合・候補コピー機能は引き続き利用できます。

## ファイルの構成（重要：別のGASプロジェクトで使います）

| ファイル | 設置する場所 | 用途 |
|---|---|---|
| `Code.gs` | **Webアプリ側**のApps Script | FreeBusy検索、会議室照合、メンバー保存 |
| `index.html` | **Webアプリ側**のHTMLファイル `index` | 検索画面、マスター登録確認画面 |
| `appsscript.json` | **Webアプリ側**のマニフェスト | Calendar APIと必要なOAuth権限 |
| `SpreadsheetMembers.gs` | **管理スプレッドシート側**のApps Script | メーリス一括展開、上部メニュー |
| `LICENSE` / `CHANGELOG.md` | GitHub | ライセンスと更新履歴 |

**注意：`SpreadsheetMembers.gs` をWebアプリ側へ貼り付けないでください。** 管理スプレッドシートと紐づく（コンテナバインド型）スクリプトで使います。Webアプリ側の `Code.gs` に `syncGroupsToMembers` が含まれないのは設計どおりです。

## 初めて導入する方

1. [Google Apps Script](https://script.google.com/) で新しいプロジェクトを作り、`Code.gs` 全文をスクリプトファイル、`index.html` 全文をHTMLファイル名 `index` として貼り付けます。
2. プロジェクト設定の「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にして、同梱 `appsscript.json` の内容に置き換えます。
3. 左側の「サービス」から Google Calendar API（高度なサービス、v3）を追加します。利用環境によりCloudプロジェクト側のAPI有効化も必要です。
4. Webアプリ側の関数 `setupSampleSpreadsheet()` を**1回だけ**実行して権限承認。実行ログに表示される管理スプレッドシートを開きます。
5. `メンバー` シートは **A列：区分／B列：表示名／C列：カレンダーID** です。架空アドレス `example.com` のサンプル行は削除し、実際の対象メンバー・会議室を設定します。会議室はA列の区分を `会議室` とします。
6. 管理スプレッドシートの「拡張機能」→「Apps Script」から**シート側の別プロジェクト**を開き、`SpreadsheetMembers.gs` の全文を貼り付けて保存します（もともと `onOpen` がある場合はメニュー追加処理を統合）。シートを再読み込みすると **「📋 メーリス管理」** が表示されます。
7. メーリス一括展開を利用する場合は、実行ユーザーがGoogleグループのメンバー情報を参照できることを確認します。最初のメニュー実行時に権限確認が表示される場合があります。
8. Googleカレンダーの「日本の祝日」を追加し、対象カレンダーに「予定あり／空き」を参照できる権限を設定します。参照権限がない場合、検索はエラーで止まります。
9. Webアプリ側の「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選びます。実行ユーザーは**「ウェブアプリケーションにアクセスしているユーザー」**、アクセス範囲は可能な限り**組織内に限定**してください。**匿名全体公開はしないでください。**
10. WebアプリURLを開いて権限を承認し、テスト用参加者で検索と登録の動作を確認します。

### メーリングリストの登録例

| 区分 | 表示名 | カレンダーID |
|---|---|---|
| 営業 | （空欄） | `sales@example.com` |

この状態で「📋 メーリス管理」→「メンバーを一括登録・更新」を選択すると、グループの**直接所属ユーザー**をA～C列に展開します。**メールアドレスだけを書いても自動展開されません。** `sales@example.com` は例示用の架空アドレスです。アクセス権やグループ設定によっては所属者を取得できません。

展開できなかった場合、元コードと同様にメールアドレスを残し、表示名には `@` より前の文字列を設定します。**その後はB列が空欄でなくなるため、再試行には対象行のB列を空欄に戻す必要があります。** Googleグループを取得できる権限がない場合や、メーリングリストではない通常のメールアドレスの場合も同様です。

### フリー入力したメンバーのマスター保存

Webアプリの「参加者のメールアドレスを追加」にアドレスを入力 → 「追加」 → 「マスターへ追加登録」の画面が表示されます。
- `しない`：今回の参加者に追加するだけで保存しません。
- `登録する`：表示名・区分を入力してシートに追加します。**Webアプリを再読み込みした後**にプルダウンに反映されます。

## 既にv1.0/v1.1をお使いの方（既存データを維持して更新）

1. 現在のWebアプリGASと**管理スプレッドシートをバックアップ**してください。
2. Webアプリ側の `Code.gs` と `index.html` を同梱の**v1.2全文**に置き換え、`appsscript.json` の内容も同梱版に揃えます。
3. **`setupSampleSpreadsheet()` は再実行しないでください。** 再実行すると新しい設定シートが作られ、設定先のIDも変更されます。既存の `MEMBER_SPREADSHEET_ID` をそのまま使います。
4. 管理スプレッドシート側で、`SpreadsheetMembers.gs` を別のスクリプトとして追加（既存の `syncGroupsToMembers` と `onOpen` は**重複させず**必要な箇所を置き換え）。保存後、シートを再読み込みします。
5. 「デプロイ」→「デプロイを管理」→対象デプロイを編集→**新バージョン**→デプロイ。Webアプリを再読み込みして、プルダウン／フリー入力／保存／候補検索／会議室照合を確認します。

## 重要：管理スプレッドシートの権限

この版はWebアプリを**アクセスしたユーザーの権限で実行**する構成です。検索のみなら管理シートの閲覧権限で動く場合がありますが、**新機能の「マスターに登録する」を使うユーザーには、管理シートの編集権限が必要です。** 編集権限を付与する相手は厳しく限定してください。

編集権限を付与できない環境では、管理者に登録を依頼する運用にするか、書き込み処理の権限分離など別設計が必要です。**権限を回避するためにWebアプリの実行ユーザーを安易に「自分」に変えないでください。** その場合、検索者本人の `primary` カレンダーを使うという既存仕様が変わります。

### セキュリティ・運用上の制約

- `addMemberToSheet` は元の最終版コードを収録しています。**重複登録防止やサーバー側の厳密な入力検証は未実装**です。利用者を限定し、登録後の一覧を管理者が確認してください。公開サービスや不特定多数向けとして使わないでください。
- Googleグループのメンバー閲覧権限がない場合、メーリス展開はできません。ネストされたグループ内の全員を再帰取得する仕組みは含めていません。
- グループ展開時、管理シートのA～C列をまとめて書き直すため、**数式や手入力データはバックアップを取り、対象3列には値だけを管理することを推奨**します。
- フリー入力で登録した社員名やメールアドレスはシートに保存されます。社外・一般公開しないでください。
- 個人の予定タイトルは取得せず、Google Calendar FreeBusy APIで「予定あり／空き」のみを照合します。共有権限不足なら停止します。
- 平日10:00〜19:00、1時間以上、30分刻み、祝日除外の候補を返します。最大31日・最大40カレンダーです。
- 会議室は空き照合のみで、予約の作成や確定はしません。
- 「日本の祝日」カレンダーが利用できないときはエラーで停止します。会社独自の休日には未対応です。
- オンラインアクセス権限・組織のOAuthポリシー・Google API利用制限により、各環境での追加設定が必要な場合があります。
- **共有用のソースコードと組織固有のデータは必ず分離してください。** 社員名、顧客名、カレンダーID、Google Workspace固有の設定値、認証情報などをGitHubにコミットしないでください。
